# Ejercicio 3 — Ciclo de vida en la práctica

## 1. Modelo de ciclo de vida

Recomendaría un modelo **iterativo**. El enunciado indica que los requisitos pueden cambiar según el feedback de los clientes piloto. Con iteraciones, el equipo puede entregar una primera versión, recoger opiniones y ajustar el sistema en ciclos sucesivos, en lugar de esperar a terminar todo el proyecto para validar el resultado.

## 2. Metodología

Aplicaría una metodología **ágil**, porque facilita trabajar en entregas frecuentes, colaborar con el equipo de negocio y adaptar las prioridades cuando se recibe feedback. Por ejemplo, se podría empezar por permitir la consulta del estado mediante el número de seguimiento y, en una iteración posterior, incorporar o mejorar la actualización desde el móvil por parte de los repartidores.

## 4. Actualización del estado de un envío

El `Repartidor` solicita actualizar el estado de uno de los envíos que tiene asignados. La operación de `Envío` recibe el nuevo estado: `EN_ALMACÉN`, `EN_REPARTO`, `ENTREGADO` o `DEVUELTO`.

Antes de cambiarlo, `Envío` comprueba que el valor recibido está entre los estados permitidos. Si es válido, actualiza su estado actual y devuelve una confirmación de que el cambio se ha aplicado. Si no es válido, mantiene el estado anterior y devuelve una indicación de rechazo para que el `Repartidor` sepa que la actualización no se realizó. Después, `Envío` puede informar del estado actualizado cuando un cliente lo consulte mediante el número de seguimiento.
